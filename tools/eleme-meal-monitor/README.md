# 外卖监控

Edge 本地扩展 v1.7.2：同时查看饿了么 / 淘宝闪购与美团外卖的待出餐数量和连接状态。支持按目标自动上报出餐；不自动接单。已移除新订单提醒、测试通知、提醒开关及通知权限。

## 安装

Edge 打开 `edge://extensions`，开启开发人员模式，选择“加载解压缩的扩展”，加载桌面“外卖监控”文件夹。已安装时保持原目录不变；按 Edge 提示确认网站权限并启用扩展。

安装/重载后尝试自动挂接已有订单页。若仍未连接，检查登录与页面地址，再手动刷新。

- 饿了么：仅门店 536928771 的订单页。
- 美团：当前打开并登录的 `waimaie.meituan.com` 今日待办订单页；链接没有门店 ID，未锁定具体门店。多个美团标签页使用首个有效监听源，不合并多家店。

## 数量与连接状态

两个平台独立更新数量。DOM 变化合并 300 毫秒后扫描，另每秒扫描计时。页面不可识别、登录过期或失联 60 秒后显示“未连接”，不会误报为 0 单。工具栏显示已连接平台总数；仅一个平台连接时加 `+` 表示总数不完整；全部失联显示 `?`。

保持两个商家页打开并登录。浏览器关闭、系统休眠、标签页休眠或网络中断时无法保证更新。可按需在 Edge 性能设置中将商家页加入不休眠列表。

界面参考 Apple Human Interface Guidelines，使用系统字体、分组卡片、浅深色、高对比度与减少动态效果适配；属于浏览器扩展，不是原生 macOS 应用。

## 目标出餐时长

面板内设置 1–180 的整数分钟，默认 15 分钟，点击保存后两个平台共用。目标用于插件内超时判断和自动出餐调度，不修改平台的时长配置，不发送桌面通知。

逐单保存每张待出餐卡片的真实计时快照，并每秒更新。面板逐单列出已用时、自定义目标剩余时间、平台倒计时；平台目标与自定义目标分开。只有页面同时给出该订单的平台时长和剩余时间时，才允许反推已用时，绝不使用用户设置的分钟数推算真实用时。达到自定义目标时显示“超时 N 单”。同时显示最长用时；只识别部分订单时显示识别数量。用时不可识别、列表未展开或页面未连接时不推算超时，不从打开插件的时间计时。

美团支持简洁卡片与完整卡片，并按取餐号去重。已根据实际简洁卡片及完整卡片结构核对；当前无待出餐订单时，无法完成所有实时倒计时样式的端到端验证。饿了么仅在含“上报出餐”按钮的待出餐卡片内读取明确的出餐用时标签；不支持的页面样式会显示“计时未识别”，不会把已出餐历史订单算入。识别依赖页面已加载内容；未加载的分页/虚拟列表订单无法读取。面板显示“已识别 X/Y 单”，数量不齐明确显示“存在漏读”。目前不能保证跨分页、未展开卡片及未验证页面样式的每一单都可识别，不会伪造已识别状态。

## 隐私与权限

读取待出餐数量、卡片订单标识/取餐号与计时标签，不读取顾客信息。订单标识仅用于逐单区分，不发送到外部。数量、用时和连接状态存于浏览器会话存储；目标分钟数、自动设置与逐单尝试记录保存在本机，重启仍保留。记录保留 48 小时用于防止重复点击。不直接调用订单接口、不下载远程代码；开启自动出餐后，通过页面出餐按钮触发平台自身的上报请求。

- `storage`：会话数量、用时与连接状态，以及本地目标时长。
- `alarms`：连接状态与本地更新检查。
- `scripting`：安装/重载后向目标订单 iframe 注入本地监听脚本。
- `webNavigation`：定位目标页面订单 iframe，不订阅全局导航。
- 网站权限仅包含饿了么商家主站、订单 iframe、美团商家主站；消息再次校验平台与页面地址。

## 本地热更新

修改仓库源码并验证后发布到桌面：

```sh
node --test tests/eleme-meal-monitor.test.mjs
node scripts/publish-eleme-extension.mjs "$HOME/Desktop/外卖监控"
```

发布脚本计算 SHA-256，先同步代码，再原子写入版本标记。扩展在 Edge 唤醒时约每 30 秒检查本地标记，也可点击“检查更新”。重载后重新挂接两个平台，不刷新商家页；开启自动出餐时将继续执行调度。新增权限仍需用户按浏览器提示确认。

无需本地服务或网络端口；仅保存源码不触发发布。页脚显示当前版本和构建哈希，不要移动已安装目录。

## v1.4.1 优先出餐漏读修复

已在真实饿了么待出餐页面确认“优先出餐”卡片：按钮不同于“上报出餐”，时间显示为“5分14秒内出餐享权益”。现同时识别两种按钮，并读取这类独立倒计时。“建议8分19秒内出餐”也是递减的剩余时间，不当成固定总时长。

“计时已识别”统计读到真实已用时或真实倒计时的订单；自定义目标判断只使用真实已用时，另显示可判断的订单数。仅有剩余时间、没有固定总时长的订单，明确显示“已用时未提供”，不使用下单分钟数或打开插件时间伪造秒级用时。

## v1.4.2 分钟级接单时间补全

优先出餐卡片没有已用时时，从该订单的“商家已接单 HH:mm”读取接单分钟，使用订单日期确定自然日，并处理跨午夜/跨年。计算已用时范围，每秒更新；例如接单时间只精确到分钟，用时范围最多相差 60 秒。不会用下单时间替代接单时间。

用时范围的下限达到目标才判定超时，上限仍小于目标判定未超时；范围跨越目标则显示“目标临界，暂不判超时”。秒级页面用时优先，无法从分钟级数据恢复精确秒数，界面会明确标注精度。平台独立倒计时继续显示。

## v1.5.0 动画进度条

逐单显示蓝色出餐进度；时间范围跨越目标时显示橙色；确认超时后显示红色超时条和累计超时时间。超时条以设定的目标分钟数为一个满刻度，超过满刻度后文字仍继续累计。分钟级用时用浅色区间标示上下界，不将区间上限当作确定超时。

每秒更新时复用原进度条节点，以 0.7 秒过渡平滑改变长度，保留列表滚动位置。超时条带轻微呼吸动画。系统开启“减少动态效果”时关闭过渡和呼吸动画。计时数据未知时不显示虚假进度条。

## v1.6.0 精简界面

总览突出待出餐与确认超时数量；两平台用紧凑卡片显示连接和数量。逐单列表按超时、临界、未知、正常排序，超时置顶。每单显示主要剩余/超时时间、一行已用时和一条动画进度条；平台倒计时可悬停在订单行查看。分钟级范围和漏读状态继续明确标示。

出餐目标默认折叠，展开后修改并保存。删除标语和重复状态说明，版本哈希退到版本号悬停信息。保留浅深色、高对比度、减少动态效果与键盘焦点支持。

## v1.6.1 数量同步提示与剩余时间排序

饿了么“进行中”完整列表已加载、每张卡片都能明确识别为待出餐或已出餐，且相同数量差异持续 3 秒时，标记“平台数量待同步”。保留平台汇总原值，已出餐订单不参与计时。列表不完整、出现未知卡片、切换页面或证据变化时立即撤回此判断，真正缺失的计时仍显示未识别。

两个平台合并按剩余时间升序排列：确认超时在前，超时越久越靠前；其余越接近目标越靠前，未知时间在末尾。优先使用自定义目标剩余时间；分钟级范围用最早可能到期时间排序（仍保留临界标注）；仅有平台倒计时时使用该值。相同时间按平台及取餐号稳定排序。

## v1.6.2 计时停滞修复

每单的已用时和平台倒计时分别保存最后一次数值变化的时间锚点。页面读数暂时不变时，本地按经过时间续计，新读数到达后校准；重复读取相同数值不重置起点。超过 10 秒没有新计时读数显示“本地续计，待页面校准”；超过 60 秒停止外推并显示页面计时未更新，暂停该单超时判断，避免把长期旧数据当实时数据。整页连接失效仍按原有机制显示未连接。

临时消息端口错误不再永久停止监听；仅扩展上下文失效时清理旧监听器。弹窗请求设 5 秒超时，自动继续重试，并防止刷新请求重叠。更新文件请求设超时，避免更新检查长时间占用消息队列。

## v1.7.0 自动出餐

按本次用户选择“到点直接自动上报”，首次加载此版本默认开启；展开“自动出餐”可随时关闭。每单在目标时长后增加一次固定随机延迟（默认 0–30 秒，可设最大 0–120 秒）。实际餐品完成情况仍由店员保证。修改目标会影响未执行订单。

只在读取到计时实际变化、按钮可见且未被遮挡时点击。仅有倒计时且无法确定已用时的订单不自动上报；分钟级接单时间采用保守下限。后台标签页休眠时不会凭本地推算点击。随机延迟仅错开操作，不模拟人工轨迹、不绕过验证码或平台风控。

点击前记录订单并核对一次执行许可，串行处理。遇到弹窗、按钮不可用、计时停滞、未出现明确“已出餐”状态或结果丢失时暂停。请人工检查后展开“自动出餐”并点“恢复”；已尝试订单不会自动重试，必要时在平台手动出餐。待出餐筛选中订单直接消失、没有明确成功标记时也会保守暂停。

美团优先使用完整订单编号；简洁卡片只有取餐号时，48 小时内相同取餐号只尝试一次，可能跳过次日同号订单，需要手动处理。未加载、屏幕外或被遮挡的订单不会强制滚动点击。平台拒绝脚本点击时暂停，不尝试绕过。

## v1.7.1 设置样式统一

自动出餐与出餐目标共用折叠设置行，默认收起。摘要显示开启、关闭或暂停状态；展开后显示开关、延迟上限和保存按钮。暂停时按钮显示“恢复”，异常原因保留在详情中。

## v1.7.2 时间文案澄清

自动出餐摘要明确显示“达标后延迟”，详情结合当前目标分钟数解释额外等待时间；延迟上限为 0 时显示“达标即上报”。时间调度逻辑不变。
