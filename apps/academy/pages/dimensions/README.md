# 尺寸标注 · Auto Office

从桌面「尺寸标注器 / 尺刻」移植，保留尺寸线、四点矩形、圆形、节点调整、缩放和图片导出。桌面源项目未修改。

在 Auto Office 的「快捷访问 → 尺寸标注」进入；员工快捷权限沿用 `AcademyAuth`。直接打开子页面会跳转主程序登录。新建图片即创建团队共享项目；「复制链接」生成带项目 ID 的 Auto Office 链接。每张图片和每条标注展示制作员工、最近修改员工。不同员工可编辑同一项目。

## 界面

项目资料库使用系统字体、语义色、原图缩略预览及制作人信息。搜索与「全部 / 我创建的」原生单选分段筛选保持等高，资料库依靠实时订阅和自动补拉更新，不提供常驻刷新按钮；请求失败仍可重试。编辑区提供独立画布、分组属性检查器、缩放与适合窗口操作；Auto Office 仅在尺寸标注子程序中扩展到 1440px，退出后恢复原布局。手机端纵向排列画布和工具，保留全部操作。

同时适配 Light / Graphite、增强对比度、减少透明度、减少动态效果以及放大字号。按钮触控区域至少 44×44px。

手机端独立采用紧凑布局：34px 标题与 44px 添加入口位于同一行，省去桌面的引导副标题；搜索框使用 17px 字号避免 iPhone 聚焦放大，分段筛选视觉高度 32px、触控高度至少 44px。项目以缩略图列表呈现，保留制作人、标注数量和更新时间；空状态没有大卡片和重复创建按钮。普通同步状态位于页底，上传进度和异常状态仍优先显示。编辑属性采用分组实体面板，遵循安全区及系统外观设置。

每次打开项目默认处于浏览模式，可点选标注、缩放和平移；点击项目工具栏「编辑」才开放绘制、节点调整、文字、样式、删除及撤销，点击「完成」恢复浏览。完成编辑不改变自动保存机制。手机双指缩放与平移在两种模式都可使用；第二指落下时取消未完成的绘制、回滚节点移动，剩余单指抬起前不重新绘制。缩放以双指中点为锚点，放大后支持单指浏览平移。触摸手势仅接管画布区域。

手机项目浏览采用占满可用高度的画布：文件名、简短同步状态、共享、导出和编辑合并到同一工具栏。点文件名展开制作人、文件大小及在线人员；制作与修改员工相同时不重复列名。正常同步和手势提示不再占据独立内容行，同步异常及冲突仍显式呈现。底部「标注」展开可滚动面板；进入编辑或填写尺寸时展开，完成编辑后收起。画布和面板独立滚动，保留双指操作、可访问标签、44px 触控范围和安全区。导出、复制等操作结果以短暂提示显示，不挤压画布。

选中标注使用独立叠加画布显示蓝色轮廓、白色衬线、固定屏幕尺寸的控制点及「已选中」文字；矩形和圆形增加淡色填充。高亮随缩放更新并避让尺寸文字，不写入共享数据或 PNG 导出。

新上传图片生成最长边 480px、最大 64 KiB 的预览，随项目写入 `meta.thumbnailPath`；主图已满足预览限制时直接复用，不重复上传。预览路径支持项目目录内带时间戳的文件名（如 `preview-1789396427100.webp`），不限定为 `preview.webp`。旧项目没有预览、预览 404 或解码失败时，按需读取主图并在本机生成小预览；不修改云端图片、数据库或标注。主图也无法读取时暂时显示占位图，下一次目录自动更新时重试。

目录只在卡片接近视口时加载预览，最多两个并发请求，缓存最多 100 张；搜索及筛选复用缓存，退出时释放对象 URL。预览会先解码验证并限制为最长边 480px、最大 64 KiB 后再缓存，避免在卡片中保留大原图。新建项目时预览生成或上传失败仍允许保存已优化的主图。

## 上传优化

导出标注图也在本机压缩：最长边 2560px、最大 512 KiB，优先 WebP，兼容回退 JPEG/透明 PNG；超限继续缩小，失败不导出大原图。导出采用点击时的画布快照，显示实际文件大小。

`image-processing.js` 在设备本机处理 JPG、PNG、WebP，原文件限制 15 MiB、2400 万像素。优先转换为 WebP，主图最长边不超过 2560px、最大 1 MiB；初始质量 0.84，超限时降低质量并按比例缩小，始终从解码后的源图重绘。保留透明背景并按 EXIF 方向解码；不放大小图。已有小文件满足尺寸和大小限制、且比重新编码结果更小时保留原格式，避免越压越大。

浏览器不支持 WebP 编码时，有透明像素则使用 PNG，否则使用 JPEG；扩展名和上传 MIME 始终对应实际编码。主图压缩失败会停止上传，不回退上传大原图。界面显示处理进度和最终主图大小。

Storage 只上传优化后的主图和可选预览；数据库只保存路径、实际尺寸、文件大小和标注数据，不保存图片二进制或 Base64。标注画布以优化后的实际尺寸初始化。已有项目不重新压缩，保持现有标注坐标。

## 存储与订阅

- 复用主程序 `ACADEMY_CONFIG` 的 `academy_progress` 表和 `cloud-files` Storage，无需新增表、SQL 迁移或额外账号。
- 项目行主键为 `doc:dimensions:<UUID>`，不会混入学习进度；`payload.meta` 保存名称、图片路径、员工和时间，`payload.annotations` 按 UUID 保存标注及删除墓碑。
- 优化主图保存为 `academy/dimensions/<UUID>/image.<ext>`，预览为 `preview.<ext>`；兼容已有项目的 `original.<ext>` 路径。新图片始终建立新项目，避免替换团队正在标注的底图。
- 项目内使用 `postgres_changes`，按精确主键过滤。相同项目使用相同 Presence 主题显示在线员工。目录使用 Broadcast 通知新项目，30 秒兜底刷新；列表每页 100 条，只查询 metadata，不下载全部标注或图片。
- 拖动结束才保存，输入延迟 450 ms 合并发送。保存用 `PATCH ... user_id=eq.<id>&ts=eq.<base>` 做原子版本校验；版本严格递增，服务端返回空行则重新读取合并。
- 不同标注自动合并。同一条标注的编辑/删除冲突保留本机内容，允许选择团队版本或将本机内容另存为新标注。复制时保留 `copiedFrom`，制作人记为当前员工。
- 操作队列按员工和项目写入本机 localStorage，刷新后重新打开项目会恢复；不会自动放弃未确认写入。网络恢复、重新订阅和前台切换会补拉。连接失败每 5 秒兜底读取；无修改时不写数据库。
- 上传成功但创建项目响应不确定时先读取核验，避免错误清理已被项目引用的图片；无法确认时显示状态，需刷新目录检查。未引用的上传对象可能需要后续清理。

## 权限边界

本次沿用 Auto Office 的自建员工登录和现有数据库权限，没有改动线上 RLS。仓库中现有 `academy_progress` 策略允许 anon 访问，员工登录不是 Supabase Auth JWT；因此快捷权限和制作人字段属于应用层约束，**不构成数据库级身份验证、不可篡改审计或跨团队隔离**。项目链接也不是私密授权凭证。需要服务端隔离时，应统一升级 Auto Office 身份体系，以 Supabase Auth/受信服务签发身份，再用成员关系 RLS 同时约束数据库、Storage 和 Realtime，不能仅给本子程序增加前端检查。

## 验证

```sh
npm test
npm run build
npm run check
```

`tests/dimensions-sync.test.mjs` 检查并发合并、冲突复制、删除墓碑、离线恢复、保存响应丢失、保存中继续输入、乱序事件和存储不足。

`tests/dimensions-browser.js` 通过 Playwright CLI `run-code` 执行。先在仓库启动 `python3 -m http.server 8775 --bind 127.0.0.1`。测试使用两个员工窗口、模拟数据库/Storage/Realtime；所有外部请求被拦截，不写生产数据。截图和 PNG 导出写入 `output/playwright/`。

`tests/dimensions-images-browser.js` 同样通过 Playwright CLI 执行，使用浏览器真实编码器检查 WebP 转换、主图及预览大小限制、比例、透明像素、编码器兼容回退、EXIF 旋转、小图复用和失败拒绝。协作浏览器测试另检查缩图后的坐标尺寸及上传内容，保证数据库不包含图片数据。

`tests/dimensions-interaction-browser.js` 以 Chromium 原生触摸事件验证浏览防误写、显式编辑、完成锁定、双指缩放平移、第二指接管、节点回滚、手势取消、选中高亮与导出隔离。使用本机编辑器夹具，不连接生产数据库。

`tests/dimensions-previews-browser.js` 检查带时间戳的路径、旧项目、404/损坏预览回退、恢复联网重试、小图尺寸、缓存复用、视口懒加载和并发上限；图片及接口均为本机模拟，不写生产数据。

现有线上表通过只读 REST 查询确认可访问；真实 WebSocket 过滤订阅返回 `SUBSCRIBED`（零写入）；生产 Storage 写入及跨设备真实 WebSocket 写入链路需部署后用真实员工验证，模拟测试不能替代该项验收。

参考：[Supabase Postgres Changes](https://supabase.com/docs/guides/realtime/postgres-changes)、[Realtime 授权](https://supabase.com/docs/guides/realtime/authorization)、[Storage 权限](https://supabase.com/docs/guides/storage/security/access-control)。
